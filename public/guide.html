YOUR LEARNING GOALS

What you will learn

Run a real agent conversation and explain what your application controls at each step.

01

Agent, environment, and session

Identify the agent configuration, the environment it uses, and the session that holds your conversation. Create a session and save its ID.

02

The application and agent loop

Send a task from the browser through the Node.js host to the managed agent. Understand why API credentials stay on the server.

03

Live events and conversation history

Follow messages and lifecycle events in the activity feed. Reconnect with a session ID and see how the host combines history with live events.

04

Session state and stop reasons

Distinguish a finished turn, a pending action, and a budget pause. Inspect the returned state instead of treating every idle event as success.

05

Human decisions and tool results

With a suitably configured agent, match a pending event to Allow, Deny, or a custom tool result. Explain why approval and supplying a result are different.

06

Interrupt and verify remote work

Request an interruption, then inspect the remote session. Learn why closing a browser does not stop agent work and why claimed artifacts need checking.

By the end: you can create, observe, reconnect to, and inspect a managed agent session, and explain when the host must make a decision.

FROM SETUP TO YOUR FIRST CONVERSATION

How to run this application

Follow these steps in order. Use PowerShell for the commands and keep the server terminal open while you use the app.

  1. Open the C01 application folder

    Install Node.js 20 or later with npm. From the presentations folder, open the app directory:

    cd .\lesson-c01\lesson-c01-app

    If your terminal is already inside lesson-c01-app, continue with step 2. This is the folder containing package.json.

  2. Install the dependencies

    npm install

    Wait for the command to finish. You normally do this once after downloading the app, or again when its dependencies change.

  3. Configure your local environment

    Keep your existing .env. If it does not exist, create it from the example:

    if (!(Test-Path .env)) { Copy-Item .env.example .env }

    Open .env in your editor and fill in your workspace credentials and resource IDs:

    ANTHROPIC_API_KEY=your_api_key
CLAUDE_MANAGED_AGENT_ID=your_agent_id
CLAUDE_MANAGED_ENVIRONMENT_ID=your_environment_id
PORT=3000

    Your Anthropic workspace must have Managed Agents access. These example values are placeholders; your real key stays in the server's .env file. Restart the server after changing it.

    Need an agent ID or environment ID?

    After setting your API key, create only the resources you are missing:

    npm run create-agent
npm run create-environment

    Each command prints an ID to copy into the matching .env entry. Each run creates a new remote resource, so save and reuse the IDs.

  4. Start the server and open the page

    npm start

    When the terminal prints Listening on http://127.0.0.1:3000, the app is ready. Open http://127.0.0.1:3000 in your browser. If you changed PORT, use that port instead.

    The terminal stays busy because it is serving the page. You can now use the application.

  5. Create a session and send your first message

    Open the session lab, click New session, and wait for the connection. Enter this example in Your message:

    Explain what an agent session is in one sentence.

    Click Send message. Watch the activity feed and save the returned session ID. New sessions use a 50¢ list-cost budget; provider usage can incur charges and in-flight work can exceed the cap.

  6. Inspect the outcome, reconnect, and stop deliberately

    Use Inspect session and read the stop reason. end_turn means the turn finished; requires_action means the host must respond; budget_reached means work is paused by the budget.

    To reconnect, enter the saved session ID and click Connect. When you return from this guide in the same browser tab, the app fills in your previous session ID automatically; click Connect to resume viewing its events.

    To request a stop, click Interrupt work and confirm the session is idle. Press Ctrl+C in the terminal when you want to stop the local server; this alone does not stop remote work.

Optional next exercise: the standard agent may never request a pending action. The app's README explains how to configure the separate pending-action demo agent and try both approval and custom-result flows.
